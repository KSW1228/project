[슬라이드 1]안녕하세요, 리눅스 서버 시스템 구축 및 자동화 구성을 발표할 3조 김승우, 정장수, 양동연, 임건형입니다. 저희는 온프레미스 분산 환경에서 핵심 서버 기능을 직접 구축하고, 이걸 Ansible로 자동화하는 것까지 진행했습니다.

[슬라이드 2 ]발표는 프로젝트 개요, 팀 구성과 역할, 수행 절차와 방법, 그리고 마지막으로 실제 수행 결과 순서로 진행하겠습니다.

[슬라이드 3 ]
저희 프로젝트의 주제는 온프레미스 분산 인프라 위에 핵심 ICT 서버 기능을 구현하고, 이를 IaC(Infrastructure as Code) 방식으로 자동화하는 것입니다. 웹·DB·인증 서버부터 DNS, 파일 공유, 메일, 리포지터리까지 실무에서 쓰이는 서버 기능 전반을 다뤘습니다. 환경은 VMware Workstation 위에서 Rocky Linux, Alma Linux, Windows Server를 함께 구성했고, 가용성을 위해 웹 루트와 DB 데이터 디렉터리는 RAID1과 LVM으로 무중단을 확보했습니다. 그리고 이 모든 구축 과정을 Ansible 롤 기반으로 자동화했습니다.

[슬라이드 4 ]역할은 네 명이 기능별로 나눴습니다. 김승우 님이 웹·DB·인증 서버, 정장수 님이 DNS와 SAMBA·NFS 파일 공유, 양동연 님이 메일 1번 서버와 웹메일·FTP, 임건형 님이 메일 2번 서버와 웹메일·리포지터리를 맡았습니다. 각자 독립적으로 기능을 구현하되, 최종적으로는 모든 서버가 도메인 기반으로 서로 유기적으로 연동되도록 설계했습니다.

[슬라이드 5]이건 저희 자동화의 큰 그림입니다. Ansible 제어 노드 한 대가 playbook을 실행하면, 먼저 FreeIPA 인증 서버를 구축하고, 그다음 각 서버를 역할별로 원격 설치합니다. 웹·DB는 httpd와 MariaDB, DNS·파일은 named와 samba, 메일과 FTP는 postfix와 vsftpd, 이런 식으로 그룹과 롤로 묶어서 한 번에 배포되도록 구성했습니다.

[슬라이드 6]저희 인프라의 중심에는 FreeIPA 인증 서버가 있습니다. 계정과 인증, 권한 정책을 전부 여기서 중앙 관리합니다. 모든 서버는 IPA 클라이언트로 묶여서 키로만 접근이 가능하고, 관리자 직접 접근은 차단하고 필요한 sudo 권한만 부여했습니다. 엔지니어는 본인 개인 계정으로만 접속하게 되어 있습니다.

[슬라이드 7]보안은 네 가지 축으로 강화했습니다. 첫째,  공개키를 인증 서버에 한 번만 등록하면 비밀번호 없이 모든 서버에 안전하게 접속할 수 있습니다. 둘째, 일반 사용자에게는 패키지 설치 같은 꼭 필요한 작업만 sudo로 허용해서 책임 추적성을 확보했습니다. 셋째, root 로그인을 패스워드 인증을 막고, 일반 유저의 su -까지 막아서 권한 상승 경로를 봉쇄했습니다.

[슬라이드 8 ]이 그림은 외부 관리자가 접속할 때 실제로 어떻게 통제되는지를 보여줍니다. 외부에서 접속하면 공개키 인증만 통과하고 비밀번호 로그인은 차단됩니다. 서버에 들어와도 root 직접 로그인은 막혀 있고, su -는 거부되며, 일반 작업은 오직 sudo로만 실행됩니다. 핵심은 키를 중앙에서 관리하기 때문에, 한 서버에서 다른 서버로 이동(측면 이동)할 때 키를 다시 배포할 필요가 없다는 점입니다.

[슬라이드 9 ]마지막으로 이 구성도는 모든 서버가 IP가 아니라 도메인으로 서로를 찾아 통신한다는 걸 보여줍니다. 워드프레스는 db.ksw.com으로 DB를 조회하고, 두 메일 서버는 MX 레코드 기반으로 서로 메일을 주고받고, 파일 서버는 허용된 대역만 SMB·NFS 공유와 FTP 전송을 하도록 했습니다. 즉, 역할 1번부터 4번까지가 도메인 기반으로 하나로 묶여 동작합니다.

[슬라이드 76]
여기서부터는 자동화 부분입니다. 저희는 Ansible 서버 한 대를 만들어서, 이 한 대로 모든 서버를 자동으로 구축하고 연동되도록 구성했습니다. Ansible 서버에서 명령어 한 번이면 FreeIPA 인증 서버가 구축되고, 각 서버에 맞는 일반 사용자가 생성되면서 권한까지 부여됩니다. 이어서 DNS 서버가 구축되어 서버 간 통신을 도메인으로 확인하고, 나머지 웹·DB·메일·NFS·SAMBA·FTP까지 전부 설치·구현됩니다.

[슬라이드 77]
이건 자동화 코드의 폴더 구조입니다. 핵심은 main.yaml 하나만 실행하면 IPA 서버부터 웹·DB까지 모든 서버가 순서대로 구축되고 연동된다는 점입니다. 이 구조의 장점은, 서버가 늘어나도 hosts에 한 줄, group_vars에 변수만 추가하면 같은 플레이북으로 자동 구성된다는 점입니다.
실행은 네 단계입니다. 주소록 세팅, FreeIPA 설치와 유저 등록, 클라이언트 가입과 보안 적용, 마지막으로 RAID·웹·DB·DNS 구축 순입니다.
FreeIPA 인증 서버에서는 중앙 계정 인증과 정책 관리를 수행하고, sudo rule 정책에 따라 일반 사용자가 생성되도록 했습니다. 일반 사용자는 중앙 FreeIPA에 공개키를 등록해서 모든 서버에 키로만 접근할 수 있고, 관리자 접근은 막고 sudo 권한만 부여했습니다.
조금 더 예를 들면, 외부 관리자가 노트북이나 개인 PC에서 서버에 접속할 때 root로는 접근이 안 되고, 일반 사용자 계정으로 개인키 인증을 통해서만 접속할 수 있습니다. 이렇게 설계한 이유는, 예를 들어 DB 서버에서 DNS 서버로 접근할 때 원래라면 ssh-copy-id로 키를 일일이 공유해야 하는데, 키를 중앙에서 관리하기 때문에 키 재배포가 필요 없어 효율이 올라가기 때문입니다.
DNS 서버는 모든 도메인 이름을 풀이해서, 웹·메일·DB 서버를 IP가 아닌 도메인으로 접근할 수 있게 했습니다. 그리고 웹·DB·NFS·FTP처럼 파일이 많이 관리되는 서버는 RAID와 LVM으로 구성해 가용성을 확보했습니다.

[슬라이드 78~79 ]
지금 보시는 화면이 main.yaml을 실행한 결과입니다. IPA 서버의 user-find 명령어로 확인해 보면 모든 키가 등록되어 있는 걸 볼 수 있습니다. 그리고 화면처럼 web 서버, file 서버, mail 서버에서 일반 사용자를 따로 등록하지 않았는데도, 일반 사용자로 로그인해서 접속할 수 있습니다.
여기서 su - 명령어를 입력하면 권한이 거부되어 접근이 안 되고, ssh root로 root 접근을 시도해도 차단되는 것을 확인할 수 있습니다. 반면 sudo 권한은 정상적으로 동작합니다.
또 중앙 FreeIPA 서버에 공개키를 등록해 뒀기 때문에, web 서버에서 ssh web@ns.jjs.io를 입력하면, DNS 서버에 web 유저를 따로 만들지 않았어도 접근이 가능한 것을 볼 수 있습니다.

[슬라이드 80~81 ]
다음은 DNS입니다. ydy.io.zone을 보시면 정방향으로 메일 서버와 FTP 서버가 등록되어 있고, 역방향을 보시면 모든 서버의 DNS가 등록되어 있는 것을 확인할 수 있습니다. 그리고 가용성을 위해 슬레이브 서버를 따로 두어서, 마스터가 업데이트되어도 슬레이브가 살아 있는 것을 확인할 수 있습니다.

[슬라이드 82~84 ]
디스크 부분입니다. 각 웹 서버와 DB 서버에서 sdb를 강제로 제거했는데도 데이터베이스와 웹 서버가 그대로 살아 있는 것을 보실 수 있습니다. 그리고 디스크를 다시 복구해도 정상적으로 재동기화되어 잘 동작하는 것을 확인할 수 있습니다.

[슬라이드 85~86 ]
웹과 메일 서버는 원래라면 GUI 환경에서 직접 워드프레스나 라운드큐브를 설치해야 하는데, 저희는 Ansible 코드로 각 서버와 DB를 연동했기 때문에 도메인 이름으로 접근하면 바로 설치 완료된 화면을 볼 수 있습니다.

[슬라이드 87 ]
또 서로 다른 메일 서버에서 도메인 기반으로 메일이 오가는 것도 확인할 수 있습니다.

[슬라이드 88~89]
파일 서버도 웹 서버와 연동되어, 테스트 파일을 생성하면 서로 연동되는 것을 볼 수 있습니다. SAMBA도 마찬가지로 Windows 서버와 파일 서버가 연동되는 것을 확인할 수 있습니다.

[슬라이드 90~91]
FTP 서버는 보시는 것처럼 호스트에 FTP 서버의 도메인을 입력하고, 사용자는 FreeIPA로 인증합니다. 서로 룰을 공유하고 있기 때문에 web·db·FreeIPA에서 생성된 유저는 모두 접근이 가능합니다.
